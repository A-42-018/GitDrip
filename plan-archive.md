# TRACK D — UI Upgrade (Glassmorphism)

## Goals
- Professional, calm, dark-first "frosted glass over aurora gradient" look; light theme supported.
- No behaviour change: ViewModel, Room, engine, bridge untouched. Existing semantics/a11y (A11y.kt, headings, 48dp targets, merged Stat nodes) must survive every phase.
- Works on minSdk 26: real backdrop blur only where it is cheap and supported, graceful translucent fallback elsewhere.

## Current UI baseline (audited)
- Plain Material3 `TopAppBar`/`Card`/`ListItem`/`OutlinedButton`; dynamic color (API 31+) else default M3 scheme; no custom typography/shapes/spacing.
- Almost all screens live in `MainActivity.kt` (Dashboard, ProjectList, NewProject, ProjectDetail, Bar, Stat) + `ProjectTabs.kt`, `ScheduleTab.kt`, `HistoryUi.kt`, `GitHubUi.kt`, `SetupScreen.kt`, `SettingsScreen.kt`.

## Design language
| Token | Spec |
|---|---|
| Background | Dark: vertical gradient #0B1020 → #121B3A; 3 blurred "orbs" (indigo #6366F1, cyan #22D3EE, magenta #EC4899) at 18–28% alpha, static (no animation by default). Light: #EEF2FF → #F8FAFC with softer orbs |
| Glass surface | Fill white 8–12% (dark) / white 55–70% (light); 1dp border gradient (white 28% → 4%); inner top highlight; radius 20dp cards, 28dp sheets, 14dp controls |
| Elevation | No Material shadows; layered glass levels: L1 card (8%), L2 raised/dialog (14%), L3 pressed/selected (20%) |
| Accent | Primary indigo→cyan gradient for primary buttons/FAB; success #34D399, warning #FBBF24, error #F87171 (state badges, never colour-only: icon + text) |
| Type | System sans (no font download): Display 32/Semibold, Title 20/Semibold, Body 15, Label 12 caps-tracking; monospace for hashes/paths/logs |
| Spacing | 4dp grid: 8 / 12 / 16 / 24; screen padding 16dp; edge-to-edge with system bar insets |
| Motion | 200–300ms fade+slide nav transitions, press scale 0.98, list item fade-in; respects "remove animations" |
| Icons | `material-icons-extended` is NOT added (APK size); use core icons already available + small custom ImageVector if needed |

## Technical approach (decisions)
1. **Fake-glass first (all API levels):** gradient + orbs drawn once as the root background (`GlassBackground`), surfaces are translucent fills + gradient border. No per-card RenderEffect → cheap, no jank on S24 or low-end.
2. **Real backdrop blur = optional, U6:** evaluate `dev.chrisbanes.haze` (Compose backdrop blur, API 31+; version must match Compose BOM 2024.06 / Kotlin 1.5.14 compiler, verify before adding, otherwise skip). Apply only to top bar, bottom bar, dialogs/sheets (max 3 blurred layers on screen). API < 31 or "reduce transparency" → solid-ish fill (alpha ≥ 85%).
3. **Theme:** drop dynamic color (conflicts with a fixed brand palette); custom `GitDripTheme(darkTheme)` with `ColorScheme` mapped so every untouched M3 component still looks right (containerColor = transparent glass where used).
4. **Contrast:** text on glass must hit WCAG AA (4.5:1 body, 3:1 large) measured against the *worst* background (orb under card). Body text = white 92% (dark) / #0F172A (light). Add a pure-Kotlin contrast unit test over token pairs.
5. **Reduce transparency / high contrast:** setting-less, derived from `Settings.Global.ANIMATOR_DURATION_SCALE == 0` for motion and a manual Settings toggle "Solid surfaces" (DataStore not present → reuse existing prefs mechanism in `Secure.kt`/ViewModel only if one exists, otherwise `SharedPreferences` in the UI layer).
6. **File structure:** new package `com.gitdrip.app.ui` (`Theme.kt`, `Glass.kt`, `GlassComponents.kt`, `Screens*`); split `MainActivity.kt` so it keeps only activity + nav.

# APP WORKFLOW (user-facing)

## A. One-time setup (P10 setup screen)
1. Install Termux (F-Droid/GitHub) + GitDrip.
2. App checks: Termux installed → RUN_COMMAND permission granted → `allow-external-apps=true` set → `~/storage` linked → git/curl/jq installed.
3. App shows a one-tap copyable setup command if anything is missing.
4. Add GitHub account: paste fine-grained PAT → app validates via `GET /user` → stored in Keystore (P14) / Termux credentials file (chmod 600).
5. Disable battery optimization for GitDrip + Termux.

## B. Create project
Dashboard → "+ Project" → name → choose GitHub repo (existing, default) → branch → auto-create repo OFF → save.

## C. Import & organize
1. Project → Import → pick files / folder / ZIP (SAF).
2. App copies to shared GitDrip/<project>/source and computes SHA-256 manifest.
3. Secret scan runs immediately; flagged files (.env, keys) are excluded and shown.
4. Auto-suggest batches (by folder/type) → user renames, reorders, moves files between batches.
5. Each batch = meaningful unit + commit message (e.g. "feat: add auth module").

## D. Schedule
1. Project → Schedule → pick time(s), days, timezone, retry limit, missed-task policy (skip / run now / next slot).
2. Mapping: each slot consumes the next PENDING batch in order.
3. App registers AlarmManager alarm (+ Termux crond fallback).

## E. Execution (automatic)
```
Alarm fires
  → app creates task_id (state: SCHEDULED) in Room
  → RUN_COMMAND intent → Termux runner.sh <task_id>
  → validate task + SUCCESS? skip : continue
  → acquire project lock
  → network check (offline → PENDING_RETRY)
  → load batch → copy batch files into repo
  → git diff: no change → STOP (no empty commit)
  → secret scan (hit → BLOCK, notify user)
  → git add <files> → commit → push
  → push OK → SUCCESS, write result JSON (hash, files changed)
  → release lock
App reads result → updates Room → notification
```

## F. Failure handling
- Transient (timeout/DNS/5xx): retry 0 → +2 → +5 → +15 min; verify commit exists before re-push.
- Fatal (bad token, permission, merge conflict, invalid repo): stop, notify, user fixes → "Retry" button.
- Reboot: BOOT_COMPLETED → reload schedules → apply missed-task policy.

## G. Monitor
- Dashboard: projects, active schedules, today's tasks, success/fail counts, next run, progress per project.
- History: per run → batch, start/end, commit hash, files changed, repo link, redacted stdout/stderr, retry log.
- Manual actions: Run now, Skip batch, Retry, Pause project, Re-order remaining batches.

## H. Screen map
Bottom bar: Dashboard | Projects | Setup | Settings (Sync = icon in the Dashboard top panel)
Projects → Project Detail (Files | Batches | Schedule | History) → Run Detail
Settings (policies, notifications, backup/restore, setup check)
